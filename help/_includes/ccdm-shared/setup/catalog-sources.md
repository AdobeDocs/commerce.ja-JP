カタログソース：製品、属性、カテゴリーの権限範囲を表します。 通常、言語、オーディエンス、原産地系の境界にマッピングし、検索、フィルター、並べ替えの動作を決定します。

## カタログソースと関連する概念

カタログソースが他のマーチャンダイジングサービスの概念とどのように関連しているかを理解すると、データを正しくモデル化できます。

* **カタログ ソース** – 製品情報を提供する基礎となるデータ コンテキスト。 カタログソースは、通常、ロケール（`en-US`、`fr-CA`など）またはPIMやERPなどの外部システムから提供されるデータコンテキストを表します。 製品、属性メタデータ、およびカテゴリはすべて、カタログソースごとに範囲が設定されます。 カタログソースは、生のカタログデータの出所と、その商品の発見への影響（検索結果、フィルタリング、並べ替え動作）を定義します。

* **[カタログ ビュー](/help/optimizer/setup/catalog-view.md)** – 特定のビジネス ニーズに合わせてカタログの設定済みビュー。 カタログビューは、カタログソース（またはロケール）を選択し、製品の表示を絞り込むために[ ポリシー](/help/optimizer/setup/policies.md)を適用し、[価格表](/help/optimizer/setup/pricebooks.md)をビューに関連付けます。 単一のカタログソースを使用すると、多数のカタログビューを利用できます（例えば、ブランドや地域ごとに別々のカタログビューを持つ1つの`en-US` ソース）。 カタログビューは、そのデータをストアフロント、チャネル、オーディエンスに公開する&#x200B;*方法*&#x200B;と考えてください。

* **[カタログレイヤー](catalog-layer.md)** - ソースデータを変更せずに製品属性（名前、説明、画像、メタデータ）を変更するために、ベースカタログデータの上に適用されるレイヤー。 カタログレイヤーは、ストアフロントの表示のみに影響し、商品の発見に影響を与えない場合に使用します。

## カタログソースの入力方法

カタログソースは、カタログデータの取り込みを通じて入力されます。 そのデータをどのように提供するかは、実装によって異なります。

- **Adobe Commerce as a Cloud ServiceとCCDM**：ネイティブ同期は、Commerce Foundationからカタログデータを提供します。 Commerce Foundationで基盤となる製品とストアビュー設定を管理し、[ データ同期](data-sync.md) ワークスペースで同期を監視します。 Data Ingestion APIを個別に統合する必要はありません。
- **サードパーティのバックエンドを備えたAdobe Commerce Optimizer** – 統合により、[Data Ingestion API](https://developer.adobe.com/commerce/services/optimizer/data-ingestion/)を通じて商品とカタログのソース情報が提供されます。


## ルールと制限

* カタログソースは、新しいロケールまたはソースシステムのカタログデータがマーチャンダイジングサービスデータレイヤーで最初に受信されたときに作成されます。
* 製品の一意性は、SKU + カタログソースで決まります。
* 買い物客はカタログソースに直接アクセスすることはありません。 カタログデータは、[ カタログビュー](catalog-view.md)を介してストアフロントに公開されます。

## モデリングガイダンス

カタログ構造を計画する際には、次のガイダンスを使用します。 CCDMを使用するAdobe Commerce as a Cloud Serviceの場合、別の取り込み統合を介してカタログソースを作成するのではなく、Commerce Foundationで基になる設定を管理します。

* 各カタログ言語に個別のカタログソースを使用します。
* 商品と属性の違いが、検索、フィルタリング、並べ替え動作（検索性やフィルタリング性の設定の違いなど）に影響を与える必要がある場合は、別々のカタログソースを使用します。
* 製品と属性の違いが検索、フィルタリング、並べ替え動作を変更せずに製品プレゼンテーションに影響を与える必要がある場合は、[ カタログレイヤー](catalog-layer.md)を使用します。

>[!MORELIKETHIS]
>
> * [ カタログ ビュー](catalog-view.md) - カタログ ソースの上にフィルターされた価格ビューを設定します
> * [ カタログレイヤー](catalog-layer.md) - ソースデータを変更せずに製品プレゼンテーションを変更する
> * [ ポリシー](policies.md) - カタログ ビューの属性ベースのフィルターを作成します
> * [価格表](/help/optimizer/setup/pricebooks.md) – 様々な顧客セグメントの価格構成を管理します
> * [制限付きアクセスキー](restricted-access-keys.md) – 署名済みトークン認証によるカタログビューの保護
